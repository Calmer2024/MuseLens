# MuseLens 项目整体功能列表（产品视角）

## 一、文档目的

这份文档从产品视角总结当前 MuseLens 项目已经具备的主要能力，重点回答三个问题：

1. 这个项目现在能做什么
2. 用户在产品里可以完成哪些核心流程
3. 当前各个功能模块之间是如何协同工作的

这份文档不强调底层技术实现，而是强调用户可感知的产品能力，适合用于：

- 产品方案梳理
- 项目阶段性汇报
- 前后端协作对齐
- 后续功能规划与优先级排序

---

## 二、项目整体定位

MuseLens 是一个围绕 AI 修图工作流构建的智能修图平台。

它不只是“调用某个模型生成一张图”，而是试图把以下几件事连接成一个完整产品闭环：

- 用户用自然语言描述修图目标
- 系统理解意图并规划修图流程
- 系统生成和执行可复用的修图方案
- 用户可以在历史结果中继续编辑、分叉、回溯
- 用户可以把成功的修图方案沉淀为模板
- 用户可以在社区、模板市场、聊天系统中分享自己的成果

从产品层面看，MuseLens 的核心价值在于：

- 让 AI 修图从一次性操作变成可沉淀、可复用、可分享、可协作的长期创作过程

## 四、AI 自然语言修图

这是 MuseLens 最核心的入口能力。

### 1. 自然语言驱动修图

用户可以直接输入一句自然语言修图需求，例如：

- 把背景换成海边黄昏
- 让画面更有电影感
- 保留人物肤色自然，但整体更通透

系统会尝试理解用户意图，并规划出一套可执行的修图流程。

### 2. 自动规划修图流程

系统不会只返回一句建议，而是会生成一份真正可执行的修图方案。

这份方案在项目里叫做 `MuseDNA`，它本质上是一个可执行、可复用、可保存的修图流程描述。

从产品角度看，可以把它理解为：

- 一份 AI 自动生成的“修图配方”

### 3. 追问补充机制

如果用户需求不够完整，系统不会直接失败，而是会主动继续问问题，例如：

- 你想保留人物还是替换主体
- 你更偏向写实还是偏风格化
- 你希望作用于整张图还是局部区域

这意味着 MuseLens 的 AI 修图流程不是一次性问答，而是支持“多轮澄清”的。

### 4. 规划与执行一体化

当用户条件足够明确时，系统可以直接完成：

- 理解需求
- 生成 MuseDNA
- 执行修图
- 返回结果图

这让产品可以支持“用户一句话就开始出图”的体验。

### 5. MuseDNA 导出与复用

当一次修图效果不错时，系统不仅能产出结果图，还能保留其背后的 MuseDNA。

这意味着一次成功修图不再只是“一张结果图”，而是可以沉淀为：

- 一个可继续编辑的流程
- 一个可分享的模板
- 一个可重复应用到其他图片的方案

## 五、透镜系统

透镜系统是 MuseLens 的能力基础。

你可以把“透镜”理解为：

- 平台内部定义好的一种标准化修图能力单元

例如：

- 抠图
- 重绘
- 人像优化
- 风格迁移
- 光影增强
- 局部区域处理

### 1. 平台具备透镜注册与管理能力

当前系统支持：

- 注册透镜
- 更新透镜
- 删除透镜
- 查看透镜详情
- 重载透镜注册表

这意味着平台不是写死某几个修图功能，而是具备持续扩展新能力的空间。

### 2. 支持单透镜直接执行

除了通过 Router 自动规划，系统也支持直接执行某一个指定透镜。

这在产品上可以支持两类场景：

- 专业用户做更明确的定向操作
- 前端做某些固定功能面板时跳过大模型规划

### 3. 支持控件化精调

部分透镜支持暴露 tweak controls，也就是给前端提供可以直接调的控制项。

例如：

- 强度
- 风格程度
- 文字提示词
- 掩码区域

这样用户拿到结果图后，可以继续细调，而不是每次都重新完整发起一轮自然语言修图。

### 4. 支持遮罩输入

用户可以在前端涂抹遮罩，或者上传 PNG 遮罩，用于局部编辑。

这为产品提供了非常重要的“局部可控编辑能力”。

## 六、树状资产管理

树状资产管理是 MuseLens 与传统“一次生成即结束”类产品的重要区别之一。

### 1. 每次修图结果都不是孤立的

MuseLens 会把一张原图以及它后续的每一次修图结果都组织成一个树。

这意味着：

- 原图是根节点
- 每一次新结果都是新节点
- 节点之间记录了“从哪里变出来”的关系

### 2. 支持历史回溯

用户可以回看任意历史节点，知道：

- 这张图是从哪一步演化来的
- 它前面经过了哪些编辑

### 3. 支持多分支创作

同一张图可以往多个方向继续尝试，不需要覆盖原结果。

例如：

- 一个版本偏电影感
- 一个版本偏清透自然
- 一个版本偏商业广告风

这使 MuseLens 更像一个“创作空间”，而不是简单的结果覆盖器。

### 4. 支持当前节点切换

用户可以把某个历史节点重新设为当前节点，继续从该状态往下创作。

### 5. 支持节点标签与对比

系统支持给节点加标签，例如：

- 最终版
- 客户确认
- 备用方案

还支持两个节点之间做对比，这有助于创作决策与版本管理。

## 七、编辑会话与片段树

如果说树状资产管理记录的是“图片结果怎么演化”，那么编辑会话记录的是“用户意图和交互过程怎么演化”。

### 1. 支持编辑会话

一个项目下可以存在编辑会话，表示某一轮持续编辑任务。

### 2. 支持编辑片段

每个会话可以继续拆分成多个编辑片段，用于记录更细粒度的操作阶段。

### 3. 支持片段树结构

编辑片段也不是线性的，而是支持分支。

这意味着产品可以同时管理两棵树：

- 图片资产树
- 交互会话树

这是 MuseLens 后续做复杂创作管理的重要基础。

### 4. 记录意图、计划与消息

编辑片段支持记录：

- 用户意图
- 系统计划
- 片段消息
- 关联的结果节点

从产品层面看，这让系统不仅保存结果，也保存“为什么这样做”。

### 4. 点赞与收藏

- 点赞帖子

## 十、模板市场

模板市场是当前产品里非常关键的一块，它把“单次成功修图”变成“可复用资产”。

### 1. 模板市场的核心定位

模板市场里展示的不是抽象概念，而是：

- 用户真实跑出来的一套可复用修图模板

一个模板卡片至少会保存：

- 模板标题
- 模板说明
- 用户信息
- 原图
- 结果图
- MuseDNA
- 标签

### 2. 用户可发布模板

当用户完成一次 AI 修图后，如果效果满意，可以选择把这次修图沉淀成模板卡片。

当前支持两种发布方式：

- 基于已有资产树结果节点发布
- 直接基于 MuseDNA 与图片地址发布

### 3. 模板版本化

一个模板不止能有一个版本。

如果作者继续优化同一个模板，可以在原模板卡片上新增版本，而不是重复发一个完全新的卡片。

### 4. 模板浏览与详情

用户可以：

- 浏览模板列表
- 查看模板详情
- 看到作者信息、原图、结果图、标签、版本信息

### 5. 模板搜索与筛选

当前模板市场已经支持：

- 关键词搜索
- 标签筛选
- 分类筛选
- 作者筛选

这意味着模板市场已经具备基础的信息检索能力。

### 6. 模板收藏

用户可以收藏模板，并查看自己的收藏列表。

### 7. 我的发布

作者可以查看自己发布的模板列表。

### 8. 应用模板

这是模板市场最有价值的能力之一。

当用户点击某个模板卡片的“应用模板”按钮后：

- 用户上传一张自己的图片
- 系统把这张图绑定到模板的 MuseDNA 输入槽位
- 系统执行该 MuseDNA
- 用户得到相同风格方向的新结果图

从产品意义上说，这实现了：

- 修图经验的可复制
- 模板资产的跨用户复用

## 十一、好友聊天与内容分享

MuseLens 当前已经具备好友私聊能力，而且不是单纯文字聊天。

### 1. 好友私聊

当前系统支持一对一私聊。

为了控制社交质量，当前规则是：

- 只有互相关注的双方才能新建私聊

### 2. 聊天会话管理

系统支持：

- 获取可私聊好友
- 创建或打开会话
- 获取会话列表
- 获取消息列表
- 标记已读

### 3. 文本消息

支持普通文本聊天。

### 4. 分享帖子

用户可以把社区帖子直接分享给好友。

### 5. 分享模板

用户可以把模板市场里的模板卡片分享给好友。

这样一来，模板市场、社区和聊天系统就被连接起来了。

### 6. 分享资产树节点模板

用户还可以直接分享某个资产树节点对应的预设内容。

这意味着“创作结果”本身也可以成为社交传播对象。

## 十二、平台运行与调试支撑能力

除了面向用户的功能，项目也已经具备较完善的运行与调试支撑。

### 1. Swagger 接口调试

后端可以直接通过 Swagger UI 查看和测试 API。

这对前后端联调、接口排错非常方便。

### 2. PostgreSQL 数据库支持

项目已经支持 PostgreSQL 作为主要数据库。

### 3. pgvector 扩展能力

项目具备接入 `pgvector` 的能力，用于做语义检索与向量增强。

### 4. Docker 化启动

后端具备容器化启动支持，便于统一部署和环境复现。

### 5. 自动建表与测试体系

系统支持数据库自动初始化，同时已有：

- 单元测试
- API 测试
- PostgreSQL 集成测试

这意味着项目不只是“能跑”，还具备一定的可维护性基础。

## 十三、当前产品能力的最大特点

如果只用一句话概括 MuseLens 当前最突出的产品特点，可以概括为：

- 它把 AI 修图从一次性生成工具，推进成了一个可规划、可复用、可沉淀、可分享、可协作的创作平台

这个特点主要体现在以下几个方面：

1. 不只出图，还保存修图方案本身
2. 不只保存结果，还保存历史路径和交互过程
3. 不只允许个人使用，还支持社区传播和好友分享
4. 不只做一次性编辑，还能把成功经验沉淀成模板市场资产

---

## 十四、当前已形成的产品闭环

从产品流程上看，当前项目已经具备一个比较完整的闭环：

1. 用户上传原图
2. 用户用自然语言发起修图需求
3. Router 生成并执行 MuseDNA
4. 结果进入树状资产管理
5. 用户可继续编辑、回溯、分支创作
6. 用户可把成功结果发布为模板
7. 其他用户可浏览、收藏、应用模板
8. 用户可把模板或帖子分享到聊天与社区

这说明 MuseLens 当前已经不是单点功能原型，而是一个正在形成体系化能力的产品。

## 十五、总结

从产品视角看，MuseLens 当前已经具备以下层级的能力：

- 底层能力：透镜系统、MuseDNA、执行引擎
- 创作能力：自然语言修图、树状资产管理、编辑会话
- 沉淀能力：模板市场
- 社交能力：社区、关注关系、好友聊天、内容分享
- 工程能力：数据库、测试、文档、Docker、调试工具

因此，MuseLens 当前最适合被定义为：

- 一个面向 AI 修图场景的智能创作与资产沉淀平台
